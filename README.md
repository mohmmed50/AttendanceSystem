# نظام تسجيل الحضور (Attendance System)

تطبيق سطح مكتب بلغة Python وواجهة PySide6 (Qt) لتسجيل حضور الطلاب لحظيًا عبر مسح كود QR بالكاميرا، مع حفظ النتائج مباشرة في ملفات Excel ومزامنة تلقائية عبر Google Drive.

</div>

---

## نظرة عامة

يقرأ التطبيق كود QR الخاص بكل طالب (يحمل رقم الطالب/الـ ID) من خلال الكاميرا، ثم يسجّل حضوره في العمود المناسب من ملف Excel الخاص بدورته أو كليته، مع مراعاة عدد الجلسات (المحاضرات) اليومية، ومنع تكرار تسجيل نفس الطالب في نفس الجلسة قبل مرور فترة زمنية محددة.

الواجهة عربية بالكامل ومن اليمين لليسار (RTL)، وتعمل بدون اتصال دائم بالإنترنت — مزامنة Google Drive اختيارية وتحدث فقط عند توفر اتصال.

## أبرز المميزات

- **مسح QR بالكاميرا لحظيًا**: قراءة كود الطالب وتسجيل وقت الحضور تلقائيًا، مع صوت ونافذة تنبيه مختلفة لكل حالة (نجاح / تكرار / خطأ).
- **دعم عدة كاميرات**: اكتشاف الكاميرات المتصلة بالجهاز والاختيار بينها، مع حفظ آخر كاميرا مُستخدمة.
- **جلسات متعددة يوميًا**: يمكن للمشغّل تحديد من 1 إلى 10 جلسات حضور في اليوم؛ يضيف التطبيق أعمدة الجلسات تلقائيًا دون أي تعديل في الكود.
- **منع التسجيل المكرر**: لا يمكن تسجيل نفس الطالب في نفس الجلسة إلا بعد مرور 10 دقائق على الأقل من آخر تسجيل ناجح له.
- **استكمال جلسة سابقة**: عند إعادة فتح التطبيق في نفس اليوم يعرض خيار استكمال ملف الحضور الحالي بدلاً من إنشاء ملف جديد.
- **نسخ احتياطي تلقائي**: أخذ نسخة احتياطية من ملف الحضور كل 20 عملية تسجيل أو كل 60 ثانية (أيهما أقرب)، مع الاحتفاظ بحد أقصى 200 نسخة.
- **مزامنة مع Google Drive**: عند بدء التشغيل (وإذا توفر اتصال) يقارن التطبيق ملفات مجلد `data` المحلي بمجلد Google Drive المشترك ويحدّثها تلقائيًا عند وجود فروق.
- **تعبئة أعمدة قياسية**: يتوقع كل ملف Excel مصدر أعمدة `S | ID | Name | College | Year`، ويضيف عمود/أعمدة الحضور تلقائيًا.

## التقنيات المستخدمة

| المكوّن | التقنية |
|---|---|
| الواجهة الرسومية | [PySide6](https://doc.qt.io/qtforpython/) (Qt 6) |
| الكاميرا وقراءة QR | [OpenCV](https://opencv.org/) |
| قراءة/كتابة Excel | [openpyxl](https://openpyxl.readthedocs.io/) |
| الصوتيات | [pygame](https://www.pygame.org/) |
| مزامنة Google Drive | [gdown](https://github.com/wkentaro/gdown) |
| التعبئة كملف تنفيذي | [PyInstaller](https://pyinstaller.org/) (`AttendanceSystem.spec`) |
| حزمة التثبيت لويندوز | [Inno Setup](https://jrsoftware.org/isinfo.php) (`installer/AttendanceSystem.iss`) |

## هيكل المشروع

```
AttendanceSystem/
├── main.py                     # نقطة تشغيل التطبيق
├── requirements.txt             # متطلبات بايثون
├── AttendanceSystem.spec        # إعدادات تجميع PyInstaller
├── assets/                      # الشعار، الأيقونة، صورة العلم
├── sounds/                      # أصوات النجاح / التكرار / الخطأ
├── installer/                   # سكريبت Inno Setup وتعليمات مجلد data
└── src/app/
    ├── bootstrap.py              # بدء تشغيل الواجهة والتدفق العام
    ├── config.py                 # الإعدادات والمسارات المركزية
    ├── settings.py                # إعدادات محلية لكل جهاز (كاميرا/جلسات)
    ├── models.py                  # نماذج البيانات
    ├── logging_setup.py           # إعداد نظام تسجيل الأحداث (logging)
    ├── camera/                    # تشغيل الكاميرا وقراءة QR (Worker threads)
    ├── data/                       # القراءة والكتابة في ملفات Excel
    ├── sync/                       # مزامنة Google Drive
    ├── audio/                      # تشغيل التنبيهات الصوتية
    └── ui/                         # نوافذ التطبيق والعناصر الرسومية (widgets)
```

## التشغيل من المصدر

```bash
pip install -r requirements.txt
python main.py
```

عند أول تشغيل، ضع ملفات Excel الخاصة بكل دفعة/كلية داخل مجلد `data` (يُنشأ تلقائيًا عند أول تشغيل)، على أن يحتوي كل ملف على الأعمدة:

```
S | ID | Name | College | Year
```

راجع `installer/data_readme.txt` لمزيد من التفاصيل حول تنسيق ملفات البيانات.

## بناء نسخة تنفيذية (exe)

```bash
pyinstaller AttendanceSystem.spec
```

ولإنشاء حزمة تثبيت لويندوز، استخدم سكريبت `installer/AttendanceSystem.iss` مع [Inno Setup](https://jrsoftware.org/isinfo.php).

## ملاحظة حول الخصوصية

هذا المستودع يحتوي على **السورس كود فقط**. مجلدات `data` و`backup` و`logs` وملف `settings.local.json` مستبعدة عمدًا عبر `.gitignore` لأنها تحتوي على بيانات حضور فعلية لطلاب حقيقيين (أسماء وأرقام قومية)، بالإضافة إلى أن الملفات التنفيذية الناتجة (`dist/`, `build/`, `installer_output/`) تتجاوز الحد الأقصى لحجم الملف على GitHub.
